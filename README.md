# WIP（Work In Progress）

書きかけの文章（短文・散文・詩など）を、公開しながら直していくための個人サイトです。
Astro で作った静的サイトを、GitHub Pages で公開します。

- 公開URL：<https://hungrycyano.github.io/wip/>
- サイト名・説明文：`src/config/site.json`
- 作品の種類（短文・詩など）：`src/config/kinds.json`

---

## 作品を追加する

1. `src/works/` に `作品ID.md` という名前でファイルを作ります。
   作品ID は半角英数字とハイフン（例：`asa-no-koppu.md`）。これがURLになります（`/wip/works/asa-no-koppu/`）。
2. ファイルの先頭に、次の情報を書きます。

```yaml
---
title: 作品名
summary: 一覧に出す短い説明（1〜2文）
kind: short        # src/config/kinds.json の id のどれか
status: 書きかけ    # 書きかけ / 改稿中 / ひとまず完成
tags: [夜, 海]
created: 2026-10-18
updated: 2026-10-18 # 一覧はこの日付の新しい順。手で書いた日付がそのまま出ます
thumbnail: /assets/作品ID/thumb.jpg   # 省略可
background: /assets/作品ID/bg.jpg     # 省略可
audio: /assets/作品ID/reading.mp3     # 省略可
draft: false       # true にすると公開サイトに出ません
log:               # 直した履歴の一言メモ（新しいものを上に）
  - date: 2026-10-18
    note: 3段落目を削った
---

ここから本文（Markdown）。
空行で段落が分かれます。
```

- `status` と `kind` に決まっていない値を書くと、ビルドがエラーになり、どの作品のどこが違うかが表示されます。
- 詩（`kinds.json` で `"keepLineBreaks": true` の種類）は、行末の改行がそのまま表示されます。ほかの種類では、空行で段落が分かれ、段落の中の改行はつながります。
- 画像・音声は `public/assets/作品ID/` に置き、先頭情報には `/assets/作品ID/ファイル名` と書きます（`/wip` は自動で付きます）。
  音声ファイルは 1ファイル100MB未満、サイト全体で1GB程度までを目安にしてください。

### テスト用の作品

`src/works/test-short.md`・`test-poem.md`・`test-prose.md`・`test-novel/`（章分けした長編）は動作確認用です。テスト用の素材は `public/assets/test-prose/`・`public/assets/test-poem/` にあります。本物の作品を置いたら、`test-` で始まるファイル・フォルダは削除してかまいません（元のひな形は `sample/` に残っています）。

## 章分けした長編

長編は、作品IDの名前のフォルダを作り、その中に作品の情報と章を分けて置きます。

```
src/works/toudaimori/
  index.md   作品の情報（先頭情報は1ファイルの作品と同じ）。本文は「まえがき」として目次の上に出ます（空でもよい）
  01.md      第1章
  02.md      第2章
  …
```

- 章のファイルの先頭情報は、章の題名だけで足ります。章ごとに背景・音声を変えたいときは `background:`・`audio:` も書けます。`draft: true` の章は公開されません。

```yaml
---
title: 春
---

ここから第1章の本文。
```

- 章は**ファイル名の順**（01, 02, … 10）に並びます。番号は2けた（01）にしておくと見分けやすいです。
- 作品ページ（`/wip/works/toudaimori/`）に目次が出て、章のページ（`/wip/works/toudaimori/01/`）には「前の章／目次／次の章」が付きます。
- 一覧には作品が1件として出て、「全○章」と表示されます。検索は章の本文も対象です。
- `index.md` のないフォルダに章を置くと、ビルドがエラーになって知らせます。
- **GitHubに置くとき**：`src/works/` を開いて「Add file」→「Upload files」に、パソコンのフォルダ（`toudaimori`）ごとドラッグすると、フォルダの形のまま置けます。

### 編集画面で長編を書く

- 「作品の情報」の**形式**で「章分けした長編の、作品の情報とまえがき」か「長編の章」を選びます。
- 「**新規の章**」を押すと、今開いている長編の作品IDと次の番号（例：04）が入った章の下書きができます。
- 書き出すと、作品の情報は `index.md`、章は `01.md` などの名前でダウンロードされます。置く場所は画面に表示されます。

## 画像・背景・音声

- 素材は `public/assets/作品ID/` に置き、先頭情報に `/assets/作品ID/ファイル名` と書きます。
  - `thumbnail`：一覧の画像（正方形に切り取って表示）。ない作品は、種類と状態で枠を変えた代わりの表示になります
  - `background`：本文の後ろの背景（文字が読めるよう、本文の下に半透明の下敷きが入ります）
  - `audio`：本文の上に音声プレーヤー（mp3）
- 編集画面の「素材」で「**手元のファイルで確認**」を押すと、パソコンの画像・音声をプレビューに映せます（保存・送信はしません）。パスが空なら、公開するときのパスが自動で入ります。
- 音声ファイルは 1ファイル100MB未満、サイト全体で1GB程度までを目安にしてください（GitHub Pages の制限）。

## 種類（kind）を増やす・減らす

`src/config/kinds.json` だけを直します。

```json
{ "id": "essay", "label": "随筆" }
```

- 追加：1行足すだけ。トップの絞り込みや作品の検証に自動で反映されます。
- 表示名を変える：`label` だけ直します（作品ファイルは直さなくてよい）。
- 削除：1行消すだけ。ただし、その種類を使っている作品があるとビルドエラーになり、該当する作品の名前が表示されます。
- 改行をそのまま表示したい種類には `"keepLineBreaks": true` を付けます。

## 公開する

`main` ブランチに変更が入ると、GitHub Actions が自動でビルドして GitHub Pages に公開します（数分かかります）。
進み具合は、GitHub のリポジトリの「Actions」タブで見られます。

### 最初に1回だけ必要な設定

1. GitHub のリポジトリ → **Settings** → **Pages**
2. 「Build and deployment」の **Source** を **GitHub Actions** にする

### GitHub の画面だけで作品を追加・修正する

1. リポジトリの `src/works/` を開く
2. 「Add file」→「Upload files」で、書き出した `.md` ファイルを置く（同じ名前なら上書き）
3. 「Commit changes」を押す → 数分後に公開サイトに反映

### リポジトリ名を変えたとき

`astro.config.mjs` の `base`（今は `/wip`）を、新しいリポジトリ名に合わせて直してください。

## 編集画面（パソコン専用）

`https://hungrycyano.github.io/wip/edit/` を開きます（サイトのどこからもリンクしていません）。スマホで開くと「パソコンで使ってください」と表示されます。

- **左が本文、右がプレビュー**。プレビューは公開ページと同じ部品・同じCSSで作っているので、公開したときと同じ見た目になります。「本文だけ」「プレビューだけ」にも切り替えられます。
- 上の「作品の情報」で、題名・作品ID（ファイル名）・説明・種類・状態・タグ・日付・更新メモを編集できます。
- **自動保存**：入力すると、少し待ってからこのブラウザに保存されます（作品ごと。下書きは何作でも持てます）。`Ctrl+S` ですぐ保存することもできます。
- **書き出し**：「書き出し（.md）」で、先頭情報つきのMarkdownファイルをダウンロードします。「書き出すとき更新日を今日にする」のチェックで、更新日を今日に変えるかどうかを選べます。
- **読み込み**：「ファイルを読み込む」で手元の `.md` を開けます。「サイトの作品を開く」で、公開中の作品から直しはじめることもできます。
  一度でも編集画面を使ったブラウザ（パソコン）では、作品ページの下に「編集画面で開く」が出ます（読む人には見えません）。
- **参考を開く**：パソコンの画像・PDF・テキスト・音声を、画面の右側に表示します。ファイルはどこにも保存・送信しません（再読み込みすると消えます）。✕ か `Esc` で閉じると、元の画面に戻ります。

### 公開までの流れ

1. 編集画面で書く（自動でブラウザに保存）
2. 「書き出し（.md）」でファイルにする
3. GitHub の `src/works/` に「Upload files」で置く（同じ名前なら上書き）→ 数分で公開

### 注意

- **下書きは、このブラウザの中だけに保存されています。** ブラウザの閲覧データ（Cookieとサイトデータ）を消すと、下書きも消えます。別のパソコンや別のブラウザからは見えません。こまめに「書き出し」をしてください。しばらく書き出していないと、画面の上に知らせが出ます。
- 編集画面は**鍵ではなく、見えにくくしているだけ**です。URLを知っていれば誰でも開けますが、下書きはその人のブラウザに保存されるだけなので、公開サイトの内容を書き換えることはできません。検索の索引にも入りません。
- 同じブラウザで編集画面を2つのタブで開いた場合は、新しく保存した方の内容が残ります。

## パソコンで動かしてみる（任意）

Node.js 22 以上が必要です。

```sh
npm install
npm run dev      # http://localhost:4321/wip/ で確認（検索はビルド後のみ）
npm run build    # 公開用のファイルを dist/ に作る（検索の索引も作る）
npm run preview  # ビルドしたものを確認
```

## 表示設定について

縦書き／横書き、文字の大きさ、行間、1行の文字数は、読む人のブラウザに保存され、次に開いたときも引き継がれます。
1行の文字数を画面に収まらない値にしたときは、画面いっぱいで止まります（設定欄に「画面いっぱい：約○字」と出ます）。

## ファイルの構成

```
src/
  config/site.json     サイト名・説明
  config/kinds.json    作品の種類
  works/*.md           作品（1作品＝1ファイル）
  content.config.ts    作品の先頭情報の決まり（検証）
  lib/render.ts        本文の表示（公開ページと編集画面のプレビューで共通）
  lib/frontmatter.ts   作品ファイルの読み込み・書き出し（編集画面用）
  lib/parts.ts         状態ラベル・更新メモなどの表示部品
  styles/wip.css       見た目（すべての画面で共通）
  scripts/             表示設定・位置スライダー・検索の動き
  scripts/editor/      編集画面の動き（自動保存・書き出し・参考パネル）
  pages/               ページ（トップ・作品ページ・編集画面 /edit/）
public/assets/         公開する画像・音声
sample/                テスト用作品と種類設定のひな形
```
